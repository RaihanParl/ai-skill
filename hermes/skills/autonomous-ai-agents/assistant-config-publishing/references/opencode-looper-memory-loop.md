# OpenCode looper memory loop

Session lesson: `/looper` should not only scaffold loop design. If loop work surfaces durable learnings, constraints, decisions, or verified failures, the command-level behavior must write them back to `MEMORY.md` / user memory in the same turn, then resync memory.

Practical pattern:
- Keep the command stub terse.
- Put the policy in always-on instruction surface (`AGENTS.md` / equivalent) so it applies user-wide.
- Mirror same change into repo-backed assistant config in same commit.
- Treat memory writeback as part of loop finish, not optional note.

Use this as a reminder when updating user-level assistant commands that are meant to improve across sessions.
